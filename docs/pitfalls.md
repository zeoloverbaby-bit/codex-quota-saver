# 排坑表（19 个实测坑，人话版）

> 全部来自 2026-08 实机部署与排障记录。坑 1-9 是 MCP 桥部署期，坑 10-14 是桥治理期，坑 15 是模型编排期，坑 16-19 是 v1.6.x 桥加固期现场。
> 通用排障原则：**先取证再动刀**——服务器侧全绿就别动服务器，问题多半在平台侧。

## 桥部署期（坑 1-9）

1. **Windows 假 Python**：`python3` 可能指向微软商店占位符，运行即静默失败。
   排查：`command -v python3` → 输出含 `.../WindowsApps/python3` 就是假存根。解法：显式指定真实解释器路径。

2. **别管道喂安装脚本**：`curl | bash` 会让脚本读不到输入。下载后执行。

3. **Defender 会静默隔离 ngrok.exe**：先给安装目录加 Defender 排除项再下载，否则装多少次都被删。

4. **OAuth 授权的连接器，重启服务器就失效**：旧架构签名密钥每次启动随机生成 + 客户端注册表纯内存态——重启即废所有 token，表现为连接器工具全挂 / 401 / TaskGroup 报错。**（v1.6.0 已从设计上根治：bridge-guard 把密钥与 DCR 注册表落盘 `guard/state/oauth_state.json`——重启桥授权依然有效，只有删掉该文件才需重新授权）**

5. **ChatGPT @ 菜单找不到连接器**：@ 列表是对话快照——旧对话永远看不到新连接器。新建对话 + 输入全名。

6. **工具调用静默无返回**：先看应用详情「操作」栏有没有工具列表。「尚无可用的应用操作」= 连接器还是空壳，调用被平台静默丢弃（连报错都没有）。别急着下「平台禁用」的结论。

7. **config 写 max 却显示 medium**：Codex App 设置-配置要开启 reasoning effort 档位，否则被静默降级。**会话实际显示为准。**

8. **子代理可能偷偷继承父模型**（官方 issue #32587 无修复）：第一次用子代理后核对实际模型。

9. **改 AGENTS.md 不生效**：改完必须开新会话。

## 桥治理期（坑 10-14）

10. **服务器一重启，连接器就全挂（TaskGroup/401）**：旧架构根因同坑 4（密钥随机生成 + 注册表内存态），**v1.6.0 已根治**（`guard/state/oauth_state.json` 落盘）；B7 之后仍见 TaskGroup 报错是平台运行时 bug（见坑 12），与重启无关。
    取证三判：① 端到端冒烟（curl 直接打服务器，工具返回 200 = 服务器没坏）；② 隧道流量缓冲（ngrok 本地 API `http://127.0.0.1:4040/api/requests/http` 看请求是否到达、状态码多少）；③ JWT 解码（base64 解 payload 看 exp 是否过期——不过期还 401，就是注册表/密钥问题）。

11. **重新授权报「Unknown client_id」**：旧架构重启后服务器忘了连接器是谁。**（v1.6.0 已根治：DCR 注册表落盘 `guard/state/oauth_state.json`，服务器不会再忘记连接器）**——不是你的操作问题。

12. **连接器被「运行时禁用」，但服务器一切正常**：ChatGPT 平台侧的会话级状态。开新对话 + 放慢调用节奏 + 等 3-5 分钟冷却。别为此改服务器——乱改只会引入新变量。

13. **GitHub 连接器读私有仓库 404**：私有仓库对没权限的账号连存在性都隐藏。授权时确认登录的是仓库 owner 的 GitHub 账号——与 ChatGPT 登录邮箱无关。本地交叉验证：`git ls-remote <repo-url>`（走本机缓存凭证）能枚举 refs = 仓库真实存在，404 是账号权限问题。

14. **升级 MCP 包会覆盖本地补丁**：升级后服务器可能拒绝启动（比如 env 里 TTL 超出新版本上限）。升级前查自己的补丁记录，升级后先重打补丁再启动。

## 模型编排期（坑 15）

15. **别急着上「Sol 主 + Luna 子」官方模式**：2026-08-15 官方官宣 Sol 可以编排 Luna 舰队，但社区实测 Luna 仍被 Multi Agents V2 的 `spawn_agent` 当 V1 过滤（[#36294](https://github.com/openai/codex/issues/36294) / [#35097](https://github.com/openai/codex/issues/35097)）。本仓库的「Luna 主 + Luna 子」全程 V1 同版本委派，天然绕开——想省额度就保持现状，等修复落地再评估。

## 桥加固期（坑 16-19）

16. **双击启动器约 30 秒窗口消失、只剩 ngrok**：不是最小化 ngrok 窗口的锅——旧版密码生成器越界索引混入 NUL 字节（实测 42% 概率）→ 写进 `.secrets.local.env` → cmd 的 `for /f` 读到 NUL 即静默截断 → 两个程序没拿到变量崩溃退出。v1.6.2 已修复（按字母表实际长度取模 + 拒绝采样 + 200 次生成回归测试）。

17. **双击启动器报「Windows 无法访问指定设备、路径或文件」**：ACL 收紧误授 `(R,W)` 缺执行位——资源管理器双击 .bat 要求 X 位（cmd 直读则不需要，命令行测试发现不了）。启动器要 `(RX,W)`、secrets 保持 `(R,W)`。v1.6.1 已修复（回归测试用 icacls 真实验证执行位）。

18. **连接器「建立连接时发生意外错误」、工具列表为空**：授权成功 ≠ 连接成功。SDK 在 host=localhost 时自动启用 DNS-rebinding 防护、只放行回环 Host——经 ngrok 转发的公网请求全部 421 拒之门外。看 guard 访问日志定位：`/token 200 → /mcp 421` 即中招（首个 401 是 ChatGPT 无 token 探测的正常挑战，不必慌）。v1.6.3 已修复（显式放行公网域名，陌生 Host 仍被拒）。

19. **浏览器打开桥链接先见英文警告页**：ngrok 免费版拦截页（「You are about to visit…」）**无法用技术手段跳过**（官方明确禁止注入 skip 头，实测 ERR_NGROK_7096）。新浏览器点一次「Visit Site」即可（cookie 按浏览器持久）。v1.6.4 起启动器启动 15 秒后自动打开密码页预热，把这一步提前到启动时。

## 30 秒自救清单（桥挂了）

1. **开个新对话重试**——平台侧禁用是会话级的，新对话清零
2. 还挂 → ChatGPT 设置里点连接器**「重新连接」**→ 授权页输 OAuth 密码（密码在 `bridge/.secrets.local.env` 的 `CQS_OAUTH_PASSWORD` 行；重启桥不丢授权——`guard/state/oauth_state.json` 落盘，放心重启）
3. 还挂 → **停下，取证**（冒烟三连 + 流量检查）。服务器侧全绿就别动服务器——问题在平台侧
4. 兜底：GPT 把 `.codex/next-step.md` 全文输出 → 你人工落盘，交接永不阻塞
